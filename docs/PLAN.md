# План разработки FinTrack

Перенос HTML-макета FinTrack в компактное нативное Android-приложение:
Kotlin, Jetpack Compose, Material 3, Room, minSdk 31, без backend, авторизации,
рекламы, аналитики и облачной синхронизации.

Документ составлен до начала реализации и дополнен фактическим статусом.

---

## Статус реализации

Состояние на 14.09.2026: **MVP собран и проверен на эмуляторе** (Pixel 6, API 36).

| Проверка | Результат |
|---|---|
| Unit-тесты | 56 тестов, 0 падений |
| Инструментальные тесты Room | 11 тестов, 0 падений |
| Android Lint | 0 замечаний любого уровня |
| Debug APK | 30.5 МБ, устанавливается и запускается |
| Ручная проверка | 4 экрана, сохранение операции, валидация, ландшафт, шрифт 200%, тёмная тема, ширина 320dp |

Не проверено: запуск на физическом устройстве (телефон подключён, но отладка по
USB не включена) и пустое состояние списка операций (демо-данные создаются при
каждом создании базы, поэтому визуально до него не добраться — логика покрыта
кодом, но не проверена вживую).

### Отступления от исходного плана

| Что | Почему |
|---|---|
| AGP 9.4.0 + Gradle 9.7.1 + compileSdk/targetSdk **37** вместо AGP 8 / SDK 36 | AGP 8.13 несовместим с Gradle 9.6+, а актуальные AndroidX-библиотеки требуют AGP 9.1+ и compileSdk 37. В AGP 9 Kotlin встроен, внешний плагин `org.jetbrains.kotlin.android` не применяется |
| Кнопка «Сохранить» **не блокируется** при невалидной форме | С disabled-кнопкой ошибки валидации некуда показать: пользователь упирается в серый прямоугольник без объяснения. Нажатие раскрывает ошибки, сохранение всё равно не проходит |
| Иконки — **собственные vector drawables** из SVG-путей макета вместо `material-icons-extended` | Сократило debug APK с 60 до 30 МБ |
| Кнопка-колокольчик и попап уведомлений **убраны** | Мёртвый элемент в офлайн-приложении без backend |
| Выбор месяца — `ModalBottomSheet` вместо сетки-попапа | Popover-позиционирование на телефоне неудобно и перекрывается |

**Отступы:** 4 / 8 / 16 / 24 / 32 / 40 / 48 / 64 dp. Базовый горизонтальный отступ контента — 24dp, между карточками 16dp, между секциями 32dp.

**Радиусы:** 10 (мелкие иконки), 16 (карточки, поля, кнопки), 24 (нижняя панель), 32 (верхние углы листа), pill (круглые иконки и полосы).

**Типографика** (межстрочный 1.45): 12sp даты и подписи навигации, 13sp подзаголовки и лейблы, 14sp базовый текст, 15sp названия операций и заголовки секций, 17sp заголовок шапки и значения карточек, 26sp баланс. Начертания 600 для названий, 700 для сумм и заголовков, 800 для активного пункта навигации.

### 4.2 Общее для трёх экранов

1. Оранжевая шапка с волновым фоном: три кривые Безье в `viewBox 0 0 400 220` — белая 10%, белая 14%, чёрная 7%.
2. Белый лист контента, скруглённый сверху на 32dp и наезжающий на шапку на 20dp.
3. Плавающая синяя нижняя навигация: отступы 16dp, радиус 24dp, активный пункт с фоном `rgba(255,255,255,.14)` и pill-подложкой иконки.
4. Секция: заголовок 15sp/700 + необязательная кнопка-ссылка справа.
5. Строка операции: иконка 40dp (радиус 16) с бейджем типа 20dp, название, дата, сумма справа, разделитель 1px.
6. Stat-карточки «Доходы» / «Расходы».
7. Набор линейных иконок (stroke 2, round cap/join).

### 4.3 Что изменено при переносе на Android

| Из макета | В приложении | Почему |
|---|---|---|
| Фиксированная рамка 360×760 | `fillMaxSize` + брейкпоинт 600dp, контент `widthIn(max = 600.dp)` | Адаптивность от компактных телефонов до планшетов |
| Нет системных инсетов | edge-to-edge + инсеты в шапке, навигации и форме | Иначе жестовая панель и клавиатура перекрывают интерфейс |
| `min-height: 44px` | 48dp | Норма доступности Android |
| Подзаголовок белым 88% на оранжевом | Сплошной белый, ≥14sp | Контраст ниже AA |
| SVG-иконки набором | Vector drawables из тех же путей | Меньше вес, единый вес штриха |
| Попап уведомлений | Убран | Нет нотификаций в MVP |
| `<details>` «Показать ещё» | `AnimatedVisibility` + `rememberSaveable` | Нативный паттерн, переживает поворот |
| `<select>` категории | `ExposedDropdownMenuBox` с иконками | Нативный компонент M3 |
| Текстовое поле даты | Поле только для чтения + `DatePickerDialog` | Ручной ввод даты на телефоне — источник ошибок |
| Попап месяцев сеткой 3×2 | Стрелки «‹ / ›» + `ModalBottomSheet` | Попап на телефоне неудобен |
| Только светлая тема | Светлая основная + минимальная тёмная, dynamic color выключен | Фирменные цвета не должны подменяться обоями |
| Кнопка «Сохранить» в потоке | Достижима скроллом, форма с `imePadding` | Клавиатура не должна закрывать кнопку |

## 5. Архитектура и модель данных

### 5.1 Слои

```
Compose UI (Screen)
   ↓ события        ↑ StateFlow<UiState>
ViewModel
   ↓                ↑
UseCase (CalculateSummary, ValidateTransactionInput)
   ↓                ↑
TransactionRepository (интерфейс в domain)
   ↓                ↑
TransactionRepositoryImpl → DAO → Room
```

Одна `MainActivity`, `NavHost` с четырьмя destination: `home`, `add`, `summary` и `transactions` (последний не в нижней навигации — открывается с «Главной»). Room отдаёт `Flow`, ViewModel превращает его в `StateFlow<UiState>` через `stateIn(WhileSubscribed(5_000))`.

### 5.2 Модели

```kotlin
enum class TransactionType { INCOME, EXPENSE }

data class Category(
    val id: Long,
    val name: String,
    val iconKey: String,              // маппится в drawable
    val defaultType: TransactionType?, // null — подходит обоим
)

data class Transaction(
    val id: Long,
    val amountCents: Long,   // всегда > 0; знак задаёт type
    val type: TransactionType,
    val category: Category,
    val dateTimeMillis: Long, // epoch UTC
    val comment: String?,     // до 120 символов
)
```

### 5.3 Хранение

| Поле | Тип в базе | Обоснование |
|---|---|---|
| Сумма | `INTEGER`, центы | Никаких погрешностей плавающей точки при суммировании |
| Тип | `TEXT` через `@TypeConverter` | Читаемо в дампе, устойчиво к перестановке констант enum |
| Дата | `INTEGER`, epoch millis UTC | Простая сортировка и фильтрация по диапазону |
| Категория | `INTEGER`, внешний ключ `RESTRICT` | Переименование категории не ломает историю |

Индексы: `category_id`, `date_time_millis`, уникальный по `categories.name`.
Агрегация по категориям и проценты считаются в Kotlin, а не в SQL — так они покрываются обычными unit-тестами.

## 6. Дизайн-система Compose

- `Color.kt` — палитра макета плюс `FinColors` с семантикой дохода и расхода, раздаётся через `LocalFinColors`.
- `Type.kt` — `Typography` на системном шрифте, все размеры в `sp`.
- `Shape.kt` — 10 / 16 / 24 / 32 / pill + `SheetShape` для верхних углов листа.
- `Spacing.kt` — шкала отступов, `minTouch = 48.dp`, `contentMaxWidth = 600.dp`.

**Волновая шапка** реализована на `Canvas`, а не через `Shape`: нужны три наложенных полупрозрачных слоя поверх градиента. Координаты кривых взяты из SVG и масштабируются множителями `width/400` и `height/220`.

**Правила сумм** (единственный источник — `MoneyFormatter`):

```
format(cents)              → "$1,806.20"    без знака
formatSigned(cents, INCOME)  → "+$2,200.10"
formatSigned(cents, EXPENSE) → "−$230.70"   U+2212 MINUS SIGN
formatBalance(cents)         → "$1,969.40" / "−$120.30"
formatPeriodBalance(cents)   → "+$1,969.40" / "−$120.30" / "$0.00"
```

Формат жёстко привязан к `Locale.US` — иначе на русской локали получилось бы `1 806,20`.

**Формат даты** (`DateFormatter`, на `java.time`): список — `08 апр., 09:30`; заголовок периода — `Апрель 2026`; разделители полного списка — `Сегодня` / `Вчера` / `08 апреля 2026`; поле формы — `08.04.2026`. Названия месяцев заданы явными массивами, а не через `Locale("ru")`: сокращения в ICU менялись от версии к версии, а макет фиксирует конкретный вид.

**Доступность:** смысловые иконки получают `contentDescription`, декоративные — `null`; строка операции и карточка категории озвучиваются одной фразой через `clearAndSetSemantics`; суммы в описаниях проговариваются словами с правильными падежами; тач-таргеты 48dp; высоты через `heightIn(min = …)`, чтобы выдерживать увеличение шрифта; проценты дублируются текстом рядом с полосой.

## 7. Экраны

### «Главная» (`home`)

Шапка (заголовок, приветствие, «БАЛАНС (USD)» + сумма 26sp) → две stat-карточки за текущий месяц → секция «Последние операции» с кнопкой «Все операции ›» → 6 строк → раскрывающийся блок «Показать ещё операции» (ещё 3).

Пустое состояние: нули в карточках и заглушка «Операций пока нет» с кнопкой «Добавить операцию».

### «Все операции» (`transactions`)

Полный список с заголовками-разделителями по дням, `LazyColumn` с ключами по id. Открывается с «Главной», закрывается кнопкой «Назад» и системным жестом.

### «Добавление операции» (`add`)

| Поле | Компонент | Валидация |
|---|---|---|
| Сумма | Поле с префиксом `$`, цифровая клавиатура | Обязательное, > 0, принимаются `.` и `,`, максимум 2 знака после разделителя и 9 до. Ошибка: «Введите сумму больше 0» |
| Категория | `ExposedDropdownMenuBox`, 7 категорий с иконками | Обязательное. Ошибка: «Выберите категорию» |
| Дата | Поле только для чтения + `DatePickerDialog` | По умолчанию сегодня |
| Тип | Сегментированный переключатель, по умолчанию «Расход» | Всегда валиден; категория с явным типом подставляет его |
| Комментарий | Многострочное поле со счётчиком | Необязательное, до 120 символов |

Ошибки раскрываются по нажатию «Сохранить». После сохранения — возврат на «Главную» и Snackbar «Операция сохранена». Состояние формы переживает поворот.

### «Итоги» (`summary`)

Строка периода со стрелками и выбором месяца → карточки «Доходы» и «Расходы» → широкая градиентная «Баланс за период» → «Частые категории» (сетка 2×N, топ-4 по сумме) → «Распределение расходов» (полоса-стек: топ-3 категории + «Другое» серым, легенда с переносом) → «Последние операции» за период.

Проценты считаются внутри своего типа: расходы от суммы расходов, доходы от суммы доходов; при нулевом знаменателе — 0%. Пустой период показывает заглушку.

### Навигация

Три пункта, активный подсвечен. Переходы с `launchSingleTop`, `restoreState` и `popUpTo(startDestination) { saveState = true }` — стек не растёт, скролл сохраняется. На ширине от 600dp нижняя плашка заменяется боковым `NavigationRail`.

chore: init repository and gitignore

feat(ui): app shell, navigation and all four screens
